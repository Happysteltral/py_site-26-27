# 1. Visie op programmeeronderwijs binnen ICW

Programmeertalen zijn binnen ICW geen einddoel op zich, maar een middel om computationeel denken, probleemoplossend vermogen en digitale geletterdheid te ontwikkelen. Het programmeeronderwijs vertrekt daarom vanuit inzicht, structuur en probleemoplossend denken eerder dan vanuit het memoriseren van syntax.

De didactische aanpak is sterk geïnspireerd door moderne informaticadidactiek en projectmatig onderwijs, waarbij leerlingen actief leren door:

- problemen te analyseren;
- algoritmen te ontwerpen;
- code te lezen en te interpreteren;
- toepassingen stapsgewijs op te bouwen;
- fouten te analyseren en op te lossen;
- zelfstandig oplossingen te testen en te verbeteren.

De focus ligt op transfer tussen programmeertalen. Concepten zoals variabelen, lussen, functies, objecten en datastructuren worden gezien als fundamentele informaticaconcepten die onafhankelijk zijn van een specifieke programmeertaal.

Binnen het curriculum kunnen verschillende talen gebruikt worden, zoals:

- Python
- C#
- JavaScript
- toekomstige programmeertalen afhankelijk van context en project

# 2. Didactische principes

## 2.1 Concept boven syntax

Nieuwe programmeerconcepten worden eerst conceptueel uitgelegd alvorens syntax centraal komt te staan. Hierdoor leren leerlingen abstraheren en herkennen ze patronen tussen programmeertalen.

## 2.2 Debugging als kerncompetentie

Fouten analyseren en oplossen vormt een essentieel onderdeel van programmeeronderwijs. Leerlingen leren:

- foutmeldingen interpreteren;
- logisch redeneren over code;
- testen uitvoeren;
- systematisch problemen opsporen.

## 2.3 Actief en projectmatig leren

Programmeervaardigheden worden opgebouwd via:

- begeleide oefeningen;
- mini-projecten;
- realistische toepassingen;
- iteratieve verbetering.

## 2.4 Code lezen en analyseren

Naast zelf programmeren leren leerlingen ook:

- bestaande code interpreteren;
- programmeerstructuren herkennen;
- bugs detecteren;
- algoritmes analyseren.

# 3. Vast lesstramien programmeerlessen

Elke programmeerles volgt een herkenbare didactische structuur.

## 3.1 Probleemstelling en motivatie

De les start vanuit een concreet probleem of een herkenbare toepassing.

### Voorbeelden

- score tracker
- quizapplicatie
- eenvoudige game
- webapplicatie
- dataverwerking

### Doel

> Waarom hebben we dit programmeerconcept nodig?

---

## 3.2 Computationeel denken

Het probleem wordt opgesplitst in deelproblemen.

### Hierbij komen onder andere aan bod

- algoritmisch denken;
- abstractie;
- patroonherkenning;
- decompositie.

### Ondersteuning gebeurt via

- pseudocode;
- flowcharts;
- schema's;
- klassikale analyse.

---

## 3.3 Nieuw programmeerconcept

Er wordt telkens gefocust op één centraal concept.

### Voorbeelden

- variabelen
- selecties
- iteraties
- functies
- objecten
- datastructuren

---

## 3.4 Syntax en taalconstructies

Pas na de conceptuele uitleg wordt de syntax van de programmeertaal geïntroduceerd.

### Nadruk op

- leesbare code;
- conventies;
- structuur;
- professionele programmeergewoonten.

---

## 3.5 Live coding

De leerkracht programmeert live en denkt hardop na tijdens het coderen.

Ook debugging en fouten maken krijgen expliciet aandacht.

---

## 3.6 Begeleide oefening

Leerlingen programmeren mee met ondersteuning.

### Werkvormen

- code aanvullen;
- output voorspellen;
- bugs oplossen;
- ontbrekende stukken invullen.

---

## 3.7 Zelfstandig oefenen

Oefeningen worden aangeboden op verschillende niveaus.

### Basis

Directe toepassing.

### Verwerking

Variaties op gekende voorbeelden.

### Uitdaging

Combineren van meerdere concepten.

---

## 3.8 Code lezen en analyseren

Leerlingen leren bestaande code begrijpen en verklaren.

---

## 3.9 Mini-project of challenge

Na meerdere lessen volgt een geïntegreerde toepassing.

### Voorbeelden

- Flask-webapplicatie
- eenvoudige game
- databewerking
- interactieve toepassing

---

## 3.10 Reflectie en transfer

Leerlingen reflecteren over:

- het geleerde concept;
- mogelijke toepassingen;
- verschillen tussen programmeertalen;
- efficiëntere oplossingen.

| Zelfstandig oefenen | Zelfstandig oplossingen ontwikkelen en testen |

| Debugging | Fouten opsporen, interpreteren en oplossen |

# 6. Evaluatievisie

Evaluatie binnen programmeeronderwijs focust niet uitsluitend op correcte syntax, maar vooral op inzicht en probleemoplossend denken.

## Evaluatievormen

- code analyseren;
- fouten opsporen;
- algoritmes verklaren;
- code aanvullen;
- programmeeropdrachten;
- projectwerk.

## Belangrijke evaluatiecriteria

- logisch redeneren;
- structuur van oplossingen;
- debuggingvaardigheden;
- codeleesbaarheid;
- zelfstandigheid.

---

# 7. Slotbeschouwing

Dit didactisch kader wil een consistente leerlijn creëren binnen programmeeronderwijs in ICW. Door een herkenbare structuur, sterke focus op computationeel denken en projectmatig werken ontwikkelen leerlingen niet enkel technische vaardigheden, maar ook duurzame probleemoplossende competenties.

Programmeertalen worden hierbij ingezet als instrument om fundamentele informaticaconcepten te begrijpen en toe te passen in uiteenlopende contexten.
